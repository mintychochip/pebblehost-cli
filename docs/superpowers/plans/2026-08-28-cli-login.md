# CLI Login and Build Workflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a secure interactive `pb login` command that opens PebbleHost's API-key page, stores a validated key for later agent-driven CLI calls, and migrate the status workflow/badge to a real passing Build workflow.

**Architecture:** Keep the existing single-binary `src/main.rs` command model. Add a small credential-storage boundary for platform config paths, secure file checks, atomic writes, and environment-first resolution; add login orchestration above the existing `Api::request` validation path. Rename the existing CI workflow rather than creating a duplicate, preserving its checks while adding an explicit locked build.

**Tech Stack:** Rust 2021, clap derive, reqwest, serde_json, tokio, `rpassword` for echo-disabled input, Rust standard library filesystem/process APIs, GitHub Actions YAML.

**Spec:** `docs/superpowers/specs/2026-08-28-cli-login-design.md`

## Global Constraints

- Open exactly `https://panel.pebblehost.com/account/api`; do not scrape browsers, reuse cookies, or assume OAuth/device callbacks.
- Browser launch is best-effort; print the URL on stderr and continue to prompt if the launcher is unavailable.
- Never accept or print an API key through arguments, logs, diagnostics, or success output.
- Resolve non-empty `PEBBLEHOST_API_KEY` first; an explicitly empty/whitespace value fails closed; only an absent variable falls back to the stored key.
- Store credentials in a dedicated per-user `api-key` file with `0700` directory and `0600` file permissions where supported; reject symlinks, non-regular files, and unsafe existing permissions.
- Validate a new key with `GET /api/client/account` before replacing an existing stored key.
- Keep `operations` and `update` token-free, and suppress the version reminder for `login`.
- Preserve existing command names, default pretty JSON, compact `--json`/`--verbose` output, raw text responses, and update behavior.
- Rename the workflow to `Build`, point the Shields badge at the real `build.yml`, update the release `workflow_run` dependency, and run `cargo build --all-features --locked`.

### Task 1: Add secure credential storage and resolution

**Files:**
- Modify: `Cargo.toml:13-24`
- Modify: `Cargo.lock` (Cargo-managed)
- Modify: `src/main.rs` near `CliError`, imports, and auth resolution
- Test: inline `#[cfg(test)] mod tests` in `src/main.rs`

**Interfaces:**
- `fn config_root() -> Option<PathBuf>` returns `$XDG_CONFIG_HOME`/`$HOME/.config` on Linux, `$HOME/Library/Application Support` on macOS, and `%APPDATA%` on Windows.
- `fn credential_path() -> Option<PathBuf>` appends `pebblehost-cli/api-key` to `config_root()`.
- `fn load_stored_token(path: &Path) -> Result<Option<String>, CliError>` returns `None` only when the file is absent; unsafe or malformed existing paths return a credential error.
- `fn save_stored_token(path: &Path, token: &str) -> Result<(), CliError>` creates secure directories, validates an existing destination, writes a unique same-directory temporary file with owner-only permissions, and replaces the destination.
- `fn resolve_token_from(env_token: Option<&OsStr>, path: &Path) -> Result<String, CliError>` enforces environment precedence without reading process state, making precedence tests deterministic.
- `fn resolve_token() -> Result<String, CliError>` supplies `std::env::var_os("PEBBLEHOST_API_KEY")` and `credential_path()` to the pure helper.

1. Use `std::fs::symlink_metadata`, returning `Ok(None)` only for `NotFound`.
2. Reject symlinks and non-regular files.
3. On Unix reject `permissions().mode() & 0o077 != 0`.
4. Read UTF-8, trim surrounding whitespace, and return a credential error for an empty value.

1. Create the parent directory and set its Unix mode to `0700`.
2. Validate an existing destination before replacement; reject symlinks, non-files, and unsafe Unix permissions.
3. Create a unique same-directory temporary path using the process id and current timestamp with `create_new(true)` and Unix mode `0600`.
4. Write exactly `token + "\n"`, flush and `sync_all`, then rename the temporary path over the destination on Unix; remove the temporary file on every failure.
5. On Windows use the validated destination replacement fallback that preserves the default per-user ACL and cleans up the temporary file.

Update the missing-token error to say `set PEBBLEHOST_API_KEY or run pb login` without including credential contents.

### Task 2: Add `pb login` browser, prompt, validation, and routing

**Files:**
- Modify: `src/main.rs` command enum, `run`, reminder filtering, and tests

**Interfaces:**
- `const API_KEY_PAGE: &str = "https://panel.pebblehost.com/account/api"`.
- `fn open_api_key_page() -> std::io::Result<()>` launches the constant URL with `xdg-open`, `open`, or the Windows URL launcher and returns a non-success status as an error.
- `fn prompt_api_key() -> std::io::Result<String>` calls `rpassword::prompt_password("API key: ")`.
- `async fn login_with<O, P>(base_url: &str, path: &Path, open: O, prompt: P) -> Result<Response, CliError>` where `O: FnOnce() -> io::Result<()>` and `P: FnOnce() -> io::Result<String>`; it prints the URL, ignores opener failure after an informational stderr message, rejects empty input, validates via `Api::request(Method::GET, "/api/client/account", &[], None)`, saves only after validation, and returns `Response::Text("API key saved successfully.".into())`.
- `async fn login(base_url: &str) -> Result<Response, CliError>` resolves `credential_path()` and calls `login_with` with the real opener and hidden prompt.

```rust
fn login_command_parses_without_credentials() {

#[tokio::test]
async fn login_validates_then_saves_key_even_when_browser_open_fails() {
    let server = MockServer::start().await;
    Mock::given(method("GET"))
        .and(path("/api/client/account"))
        .and(header("Authorization", "Bearer secret"))
        .respond_with(ResponseTemplate::new(200).set_body_json(json!({"id": 1})))
        .mount(&server)
        .await;
    let dir = tempfile::tempdir().unwrap();
    let path = dir.path().join("api-key");

    let response = login_with(
        &server.uri(),
        &path,
        || Err(std::io::Error::other("browser unavailable")),
        || Ok(" secret ".into()),
    )
    .await
    .unwrap();

    assert_eq!(response, Response::Text("API key saved successfully.".into()));
    assert_eq!(load_stored_token(&path).unwrap(), Some("secret".into()));
}

#[tokio::test]
async fn login_does_not_replace_key_when_validation_fails() {
    let server = MockServer::start().await;
    Mock::given(method("GET"))
        .and(path("/api/client/account"))
        .respond_with(ResponseTemplate::new(401))
        .mount(&server)
        .await;
    let dir = tempfile::tempdir().unwrap();
    let path = dir.path().join("api-key");
    save_stored_token(&path, "old-secret").unwrap();

    assert!(login_with(&server.uri(), &path, || Ok(()), || Ok("new-secret".into()))
        .await
        .is_err());
    assert_eq!(load_stored_token(&path).unwrap(), Some("old-secret".into()));
}
```
